Overview

AlgoVerse is an interactive platform that turns the abstract mechanics of data structures and algorithms into animated, explorable 3D scenes. Instead of reading that quicksort partitions around a pivot, you watch it happen — and step through it at your own pace.

It is built for the moment a concept clicks: the goal was to make the *execution* of an algorithm visible, not just its final result, so complexity and behaviour become something you observe rather than memorise.

What was built

Interactive sorting lab

Sorting algorithms rendered as live animations you can start, pause and step through — the comparisons and swaps shown as they happen, so the algorithm's behaviour is visible rather than described.

Data-structure visualizers

Trees, graphs and linear structures rendered as manipulable scenes, making their shape and the operations over them tangible instead of abstract.

3D animated execution

A Three.js rendering layer that presents execution in three dimensions, using space and motion to carry meaning that a static diagram cannot.

Step-by-step complexity

Execution broken into observable steps so the cost of an algorithm — the thing complexity notation summarises — can be watched unfolding.

How it was built

React 19 + TypeScript

Built on React 19 with TypeScript throughout, giving the visualization state a typed, predictable core as the number of algorithms and structures grew.

Three.js rendering

Three.js drives the 3D scenes, chosen so that motion and depth could do explanatory work — the animation is the teaching, not decoration on top of it.

Vite 6 build

A Vite 6 toolchain keeps the dev loop fast and the production bundle lean, which matters for a graphics-heavy app that has to stay responsive.

Tailwind 4 interface

The surrounding UI is built with Tailwind 4 — a clean, consistent shell that stays out of the way of the visualizations it frames.

Engineering challenges

Animation that teaches

The hard part of a visualization tool is not drawing the structure — it is choreographing the motion so it explains the algorithm instead of merely illustrating it. Getting the pacing and emphasis right was the real work.

Staying responsive in 3D

Real-time 3D rendering competes with UI responsiveness for frame budget. Keeping the interface smooth while scenes animate meant being deliberate about what re-renders and when.
